🔌 Virtual Accounts API Documentation

RESTful API · OAuth 2.0 · HMAC-SHA256 · SDKs

POST /api/v1/virtual-accounts Create a new virtual account Body: { account_name, currency, client_details, sweep_config } GET /api/v1/virtual-accounts/:id Get account details & balance Response: { id, name, balance, currency, status, created_at } GET /api/v1/virtual-accounts/:id/transactions List transactions (paginated) Query: ?from=2026-06-01&to=2026-06-12&limit=100&offset=0 POST /api/v1/virtual-accounts/:id/sub-accounts Create sub-account under parent VA POST /api/v1/virtual-accounts/:id/sweep-rules Configure sweep rule (threshold/percentage/scheduled/event) GET /api/v1/virtual-accounts/:id/statements Generate & download statement (PDF/CSV/Excel/MT940) DELETE /api/v1/virtual-accounts/:id Close virtual account (requires dual authorization)

🔐 OAuth 2.0 Authentication

POST /oauth/token Content-Type: application/x-www-form-urlencoded grant_type=client_credentials&client_id=YOUR_CLIENT_ID&client_secret=YOUR_SECRET Response: { "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "token_type": "Bearer", "expires_in": 3600, "scope": "va:read va:write va:delete" }
⚠ Security best practices
  • Never expose client_secret in frontend code
  • Use environment variables for credentials
  • Rotate secrets every 90 days
  • Implement IP whitelisting for production
  • Enable HMAC-SHA256 request signing for sensitive endpoints
